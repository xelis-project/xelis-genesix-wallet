# Implementation Planning

Use a plan for complex, ambiguous, or hard-to-reverse work, or when requested.
Simple changes can proceed directly.

- Establish the intended outcome, relevant current behavior, and scope.
- Describe the smallest coherent implementation and any important contract,
  compatibility, generated-output, or migration implications.
- Resolve consequential choices from source or user intent before handing off.
- Explain meaningful tradeoffs; omit routine impact assessments and architecture
  classifications that do not help the implementation.
- Choose validation for the affected behavior and risk.
- Include documentation updates only for durable changes that need explanation.

Keep the plan specific enough to implement, without imposing a fixed template.
Ask about unresolved product choices, not facts available in the repository.
